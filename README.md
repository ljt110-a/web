# web-one · 全栈用户认证示例

一个能真正跑起来的「前端 + PHP 后端 + MySQL」项目，带完整的用户认证：
注册、登录、退出、会话管理、修改密码、邮箱验证、找回密码、后台管理，
外加一个留言板、一个私有备忘录、一个游戏板块、一个学习板块、一个小说阅读板块
与一个软件仓库（各有独立地址），一个只有管理员看得到的资源监控面板，以及一节人人都能看的「我的用量」。

## 这一版由三层组成

**前端页面 · `public/`**
`public/` 目录下的静态页面，只负责展示与交互；所有数据都通过 `fetch` 调 `/api/*` 获取，
不再存在浏览器里。

**后端接口 · `src/`**
PHP 写的注册、登录、退出、改密与后台接口；密码用 bcrypt 加盐哈希保存，
登录状态靠服务端会话表校验。

**MySQL 数据库 · `web_one` 库**
`users` / `sessions` / `visits` / `auth_attempts` / `one_time_tokens` / `messages` / `memos` / `games` /
`pomodoros` / `novels` / `novel_chapters` / `softs` 十二张表，全部用预处理参数写入；换电脑、换浏览器看到的都是同一份数据。

## 环境要求

- PHP 7.3 及以上，需要 `pdo_mysql` 与 `mbstring` 扩展（用 SMTP 发信还需要 `openssl`）
- MySQL 5.7 / 8.0，本仓库按 `127.0.0.1:3306` 配置

不确定环境行不行？直接跑体检：

```bash
php database/doctor.php
```

它会逐层检查运行环境、配置、数据库连通、表结构完整性、目录可写，并列出生产风险，
每条都告诉你「哪里不对、怎么修」。

> **`php` 不在 PATH 里怎么办？** 本文后续所有 `php xxx` 命令，都可以把 `php` 换成完整路径，
> 例如本机 phpStudy 自带的那一个：
> `E:\phpstudy_pro\Extensions\php\php7.3.4nts\php.exe database\install.php`
> **最省事的办法是直接双击 `start.bat`**，它已经包含了这个回退逻辑。

## 跑起来

### 最省事：双击 start.bat

双击项目根目录的 `start.bat` 就行，它会一口气做完：

1. 找 PHP（PATH 里找不到就自动退回 phpStudy 那个）
2. 检查配置，安装 / 升级数据库（幂等，重复跑不会覆盖已有管理员密码）
3. 挑一个能用的端口：从 8000 往后找；**如果检测到本项目已经在跑，就直接打开浏览器，不重复启动**
4. 另开一个最小化的窗口启动服务器
5. 等服务器真的能响应——不是一启动就弹浏览器，否则第一眼是「无法连接」
6. 打开默认浏览器到该地址

想停就双击 `stop.bat`，或者关掉那个最小化的 `web-one server` 窗口。

- 服务器日志：`var/server.log`
- 本次用的端口：`var/running.port`（`stop.bat` 靠它找到该停哪一个）
- 只启动不开浏览器：`php tools/launch.php --no-browser`
- 指定端口：`php tools/launch.php --port=9000`
- 只看某个端口是什么情况：`php tools/launch.php --check=8000`

> 有个坑值得记一笔：**`start.bat` / `stop.bat` 里一个中文都没有**。
> cmd.exe 是「按当前代码页逐字节」读批处理文件的，文件里一有中文就会读错行
> （切到 65001 也救不了，这是 cmd 由来已久的问题）。
> 所以中文提示与全部判断逻辑都在 `tools/launch.php` / `tools/stop.php`（UTF-8），
> 还顺带让它们能在命令行里单独跑起来验证。要改提示文字，改那两个文件。

### 手动三步

**1. 配置数据库口令**（只需一次）

```bat
copy src\config.example.php src\config.local.php
```

然后编辑 `src/config.local.php`，把 `db_pass` 改成你本机 MySQL 的密码。
也可以不改文件，用环境变量覆盖（优先级更高）：

```bat
set WEB_ONE_DB_PASS=你的密码
```

**2. 安装数据库**（幂等，重复执行不会覆盖已有管理员密码）

```bat
php database\install.php
```

**3. 启动**

```bat
php -S localhost:8000 -t public public\index.php
```

浏览器打开 <http://localhost:8000>。

> 必须通过 `http://localhost:8000` 访问。用 `file://` 直接双击 `public/index.html` 是打不通接口的：
> 没有服务器就没有 `/api/*`，页面顶部会显示一条红色提示告诉你后端没启动。

改完代码想确认没改坏：

```bash
php tests/run.php
```

它在独立测试库 `web_one_test` 上起一个自己的服务器跑完整流程，不碰你的正式数据，
跑完顺便把 `web_one_test` 留给你查。首次运行需要几秒重建测试库。

## 默认账号

| 用户名 | 密码 | 角色 | 来源 |
| --- | --- | --- | --- |
| `root` | `root` | 管理员 | `src/config.local.php` 的 `admin_user` / `admin_pass`，由安装脚本写入数据库 |

`root` 登录后导航栏才会出现"后台"按钮。**这对口令只适合本地演示**，
往外部署前一定要改掉——登录后在「个人中心 → 修改密码」里改即可：

```bat
php -r "echo password_hash('你的新密码', PASSWORD_DEFAULT);"
```

也可以把输出的一串（60 个字符）填进 SQL：

```sql
UPDATE users SET password_hash = '刚才那串哈希', password_changed_at = NOW() WHERE username = 'root';
```

改完立刻用新密码登录验证一次。数据库里从来只有哈希，没有明文，所以没法"查回"旧密码，只能这样覆盖。

## 接口一览

前缀都是 `/api`，请求与响应一律是 JSON。

| 方法 | 路径 | 权限 | 作用 |
| --- | --- | --- | --- |
| `GET` | `/api/health` | 公开 | 自检：PHP 与数据库是否连通 |
| `POST` | `/api/register` | 公开 | 注册并直接登录；带 `email` 时会发验证邮件 |
| `POST` | `/api/login` | 公开 | 登录成功才签发会话 Cookie；失败会限流 |
| `POST` | `/api/logout` | 登录 | 删除当前这一条会话 |
| `GET` | `/api/me` | 公开 | 我是谁：未登录返回 `{logged:false}` |
| `POST` | `/api/visit` | 公开 | 记一次访问，返回 PV / UV 统计 |
| `POST` | `/api/password` | 登录 | 修改自己的密码（要校验当前密码），撤销其它设备的登录 |
| `POST` | `/api/forgot` | 公开 | 发密码重置邮件；无论邮箱是否存在，响应都一样 |
| `POST` | `/api/reset` | 公开 | 用邮件里的令牌设置新密码，并撤销该用户全部会话 |
| `POST` | `/api/email/verify` | 公开 | 用邮件里的令牌完成邮箱验证 |
| `POST` | `/api/email/resend` | 登录 | 重发验证邮件 |
| `GET` | `/api/messages` | 公开 | 留言列表，支持 `?page=&perPage=`（游客也能看） |
| `POST` | `/api/messages` | 登录 | 发一条留言，请求体 `{body}`；有发帖限流 |
| `DELETE` | `/api/messages` | 登录 | 删除留言，请求体 `{id}`；限作者本人或管理员 |
| `GET` | `/api/memos` | 登录 | 自己的备忘录，支持 `?filter=all\|open\|done` |
| `POST` | `/api/memos` | 登录 | 新建备忘录，请求体 `{title,body}` |
| `POST` | `/api/memos/update` | 登录 | 部分更新，请求体 `{id,title?,body?,done?}` |
| `DELETE` | `/api/memos` | 登录 | 删除备忘录，请求体 `{id}` |
| `GET` | `/api/games` | 公开 | 游戏列表，**永远只含已上架的**（结果与调用者身份无关） |
| `GET` | `/api/admin/games` | 管理员 | 游戏列表，含已下架的（否则下架之后就没法再上架） |
| `POST` | `/api/admin/games` | 管理员 | 新增游戏 —— 这就是「预留的添加接口」 |
| `POST` | `/api/admin/games/update` | 管理员 | 部分更新，也用来上下架，请求体 `{id,...,enabled}` |
| `DELETE` | `/api/admin/games` | 管理员 | 删除游戏，请求体 `{id}` |
| `GET` | `/api/study` | 公开 | 番茄钟：登录了回自己的记录与统计，没登录只回默认时长等参数 |
| `POST` | `/api/study/pomodoro` | 登录 | 记一轮番茄钟，请求体 `{subject,minutes,elapsed,finished}` |
| `DELETE` | `/api/study/pomodoro` | 登录 | 删除一条记录，请求体 `{id}` |
| `GET` | `/api/novels` | 登录 | 书架：自己导入的书，按「最近读到」倒序，附上限与统计 |
| `POST` | `/api/novels` | 登录 | 导入一个文件，请求体 `{title?,text,filename}`；后端认章节，回新书 + 目录 |
| `POST` | `/api/novels/update` | 登录 | 改书名，请求体 `{id,title}` |
| `DELETE` | `/api/novels` | 登录 | 删一本书，请求体 `{id}`；章节由外键级联删 |
| `GET` | `/api/novel` | 登录 | 开一本书：只回书目信息与整份目录，**不含正文** |
| `GET` | `/api/novel/chapter` | 登录 | 取一章正文，参数 `?id=&seq=`；带 `total` / `hasPrev` / `hasNext` |
| `POST` | `/api/novel/progress` | 登录 | 存阅读进度，请求体 `{id,chapter,paragraph}`（章号 + 章内第几段） |
| `GET` | `/api/software` | 公开 | 软件仓库清单：**只含已上架的**，附侧栏三类计数与页头统计（结果与身份无关） |
| `GET` | `/api/software/file` | 公开 | 下载安装包，参数 `?id=`；返回的是文件流不是 JSON |
| `GET` | `/api/software/icon` | 公开 | 取本地图标，参数 `?id=`；图片流（外链图标会让 CSP 的 `img-src 'self' data:` 拦掉） |
| `GET` | `/api/admin/software` | 管理员 | 同一份清单，多了下架条目、管理字段（来源、 sha256、时间）与全站 `quota` |
| `POST` | `/api/admin/software` | 管理员 | 新增一款，请求体见 `/software` 那一页的表单字段 |
| `POST` | `/api/admin/software/update` | 管理员 | 部分更新，请求体 `{id,...}`；上下架（`enabled`）也走这一条 |
| `DELETE` | `/api/admin/software` | 管理员 | 删除一款，请求体 `{id}`；本地安装包与图标一起清掉 |
| `POST` | `/api/admin/software/grab` | 管理员 | **服务器代下载**，请求体 `{id}`；同步出网，可能要几十秒 |
| `POST` | `/api/admin/software/release` | 管理员 | 不再代下载：删本地安装包，条目与图标留着，请求体 `{id}` |
| `POST` | `/api/admin/software/identify` | 管理员 | 自动识别信息：只读仓库元数据回给表单，**不写库、不落盘**，请求体 `{githubUrl?,giteeUrl?}` |
| `POST` | `/api/admin/software/icon` | 管理员 | 上传图标：base64 塞在 JSON 里（全站写操作都是 JSON），请求体 `{id,dataUrl}` |
| `POST` | `/api/admin/software/icon/fetch` | 管理员 | 智能获取图标：按 GitHub / Gitee 仓库头像依次抓，请求体 `{id}` |
| `DELETE` | `/api/admin/software/icon` | 管理员 | 去掉本地图标，请求体 `{id}`；安装包留着 |
| `GET` | `/api/admin/users` | 管理员 | 统计 + 用户列表，支持 `?page=&perPage=&q=` |
| `DELETE` | `/api/admin/users` | 管理员 | 删除用户，请求体 `{username}` |
| `POST` | `/api/admin/reset-password` | 管理员 | 后台重置普通用户的密码，请求体 `{username,newPassword}` |
| `GET` | `/api/admin/system` | 管理员 | 资源监控快照：内存 / 磁盘 / MySQL 指标 / 采样趋势 / 诊断结论（首页「运行状态」一节与完整面板共用） |

失败时状态码是 4xx/5xx，响应体固定是 `{"error": "能直接显示给用户的一句话"}`。
所有写操作（`POST` / `DELETE`）都必须用 `application/json` 提交，否则回 `415`。

用 curl 手测两个：

```bash
curl -s localhost:8000/api/health
curl -s -X POST -H "Content-Type: application/json" \
     -d '{"username":"root","password":"root"}' localhost:8000/api/login
```

## 几个关键设计

**密码**：只存 bcrypt 哈希（`password_hash` / `password_verify`）。
额外挡掉两类「看起来有密码、实际等于没有」的情况：密码就是用户名本身、以及纯数字。
上限 72 字节是 bcrypt 的硬限制——超出的部分会被静默丢弃，与其让人误以为更安全，不如直接拒绝。

**会话**：生成 32 字节随机令牌，**库里只存它的 SHA-256 摘要**，原文写进 `HttpOnly` Cookie。
所以数据库整张泄露也拿不到可用的登录令牌。剩余寿命不足一半时自动续期，常用的人不会被半路踢下线。
每个账号最多保留 N 个登录设备（默认 5），超出踢掉最旧的——这限制的是「密码泄露后被长期潜伏」。

**改密即踢人**：改密码会撤销其它所有设备上的会话，
不然攻击者已经用旧密码登录过的那个会话会一直有效，改密码等于只改了个寂寞。

**一次性令牌**：邮箱验证与密码重置共用一套机制，同样是「库里只存摘要」；
限时（24 小时 / 30 分钟）、一次性、同一用户同一用途只保留最新一条。
密码重置还有个细节：密码强度不合规时**不会**把链接作废，
否则用户输了个太短的密码就得重新收一封邮件。

**限流**：窗口 + 计数，不引入额外的锁表状态，因此天然自愈——
最早的失败记录滑出窗口后计数自然掉回阈值以下。
按账号和按 IP 两个维度分别计数；登录成功只清账号维度的记录，
**不清 IP 维度**，否则攻击者轮流换账号撞密码就能把 IP 计数刷回零。

**防枚举**：登录失败一律回「用户名或密码错误」；找回密码对「已注册」和「未注册」的响应完全一致。
分开提示会把「哪些账号存在」白送给攻击者。

**防 XSS**：前端渲染用户名一律用 `textContent` 而不是拼 `innerHTML`。
注册一个 `<img src=x onerror=alert(1)>` 这样的账号也只会显示成字面文本。

**防 CSRF**：三层——写操作强制 `application/json`（跨站 `<form>` 设不了这个 Content-Type）、
Cookie 用 `SameSite=Lax`、再校验 `Origin` 是否与请求的 `Host` 一致。

**留言板**：读公开、写要登录。发帖限流直接用 `messages` 表自己的近期行数当依据，
不额外维护一张计数表——少一张表就少一处「计数和真实数据对不上」的可能。
删除限作者本人或管理员，`canDelete` 由后端算好返回，前端那个按钮只是提示。

**备忘录**：隔离方式是「把 `user_id` 写进每一条 SQL 的 `WHERE`」，
而不是「先按 id 查出来、再判断是不是自己的」。两者的差别在出错的时候才显出来：
前者如果哪天忘了加条件，结果是查不到数据（功能坏掉，立刻会被发现）；
后者如果哪天忘了判断，结果是能改别人的数据（越权漏洞，往往很久都没人发现）。
部分更新走的也是白名单列名，而不是把前端传来的键名直接拼进 SQL
——这条白名单现在有两道：代码里点名要改哪几个字段，构造器再拿真实列名比一遍。

## 查询构造器（`src/orm.php`）

`memos` 与 `pomodoros` 这两张私有表的读写都走它。用法一眼看得完：

```php
$rows = db_table('pomodoros')          // 表名先确认存在
    ->select('id', 'subject', 'minutes')
    ->where('user_id', $uid)           // 值一律绑参数
    ->where('elapsed', '>=', 60)
    ->orderBy('id', 'desc')
    ->limit(20)
    ->get();

$id  = db_table('pomodoros')->insert(['user_id' => $uid, 'minutes' => 25, ...]);
$n   = db_table('memos')->where('id', $id)->where('user_id', $uid)->update(['done' => 1]);
```

它**故意不是**一个完整 ORM：没有实体类、没有关联关系、不跟踪变更集，
需要 JOIN 与复杂报表的地方（`auth.php`、`visits.php`、`system.php`）仍然直接写 SQL——
那种语句用链式 API 表达出来只会更难读。它只收口三件真正会出事的事：

- **列名不能绑参数，只能白名单。** MySQL 不接受「`?` 当列名」，所以标识符这一侧没有
  「绑进去就安全」这条路。这里每个列名都先跟 `information_schema` 里这张表**真实存在的列**
  比一遍（一次请求内缓存），比不中就抛异常。附带两个好处：拼错列名得到的是一句人话，
  而不是变成对外的 500；「列名来自客户端」这种结构在写法上就走不通。
  比较符同样走白名单，`orderBy` 的方向只认 `asc` / `desc`。
- **`LIMIT` 在这套配置下绑不了参数。** PDO 关掉模拟预处理之后，
  `execute([...])` 传进去的值都是字符串，MySQL 会对 `LIMIT ?` 报
  «Incorrect arguments to mysqld_stmt_execute»（本项目就因为这个把 `pomodoro_list` 的上限
  写在字符串里）。构造器把 limit / offset 强制 `(int)` 之后才拼进语句——是整数就没有注入面。
- **没有 WHERE 的 `UPDATE` / `DELETE` 直接拒绝。** 这类事故一次就够贵。
  顺带把 MySQL 的一个坑写进注释和测试：`update` 的 `rowCount` 只算「内容真的变了」的行，
  所以改成同一个值会返回 0，**不能**拿它判断记录存不存在——要判断就再查一次。

聚合与计算列走 `selectRaw('COALESCE(SUM(finished = 1), 0)', 'finished')`：
表达式没有地方绑参数，所以它只能来自源码里的字面量，构造器再挡两道
（出现 `?` 或 `;` 就拒绝），别名也要过标识符检查。

`toSql()` 返回的语句只含 `?`、不含任何值，所以测试里可以直接断言拼装结果
（`tests/cases/13-orm.php`），而不必靠「跑一遍看看数据对不对」去反推。
按账号隔离这件事构造器不会替你决定：`where('user_id', $uid)` 仍然是每条读写都要写的条件。

## 二级页面与扩展方式

首页是一级页面（单页，板块之间靠锚点滚动）；游戏板块 `/games`、学习板块 `/study`、
阅读板块 `/read` 与软件仓库 `/software` 是**二级页面**，各有独立地址。

它们没有做成孤立的静态文件，而是走同一个前置控制器：`public/index.php` 里有一张
「路径 → 模板文件」的表，加一个页面只需要往表里加一行 ——

```php
$pages = [
    '/' => 'index.html',
    '/index.html' => 'index.html',
    '/index.php' => 'index.html',
    '/games' => 'games.html',          // 游戏板块：二级页面
    '/games/' => 'games.html',
    '/games.html' => 'games.html',
    '/study' => 'study.html',          // 学习板块（番茄钟）：二级页面
    '/study/' => 'study.html',
    '/study.html' => 'study.html',
    '/read' => 'read.html',            // 阅读板块（小说）：二级页面
    '/read/' => 'read.html',
    '/read.html' => 'read.html',
    '/software' => 'software.html',    // 软件仓库：二级页面
    '/software/' => 'software.html',
    '/software.html' => 'software.html',
];
```

每个页面都写三种写法：不带斜杠的正式地址、带斜杠的、以及真实文件名——
少一种就会有人从收藏夹或从别人的链接点进来时吃到 404。

这样做的好处：`/games` 这种没有扩展名的地址照样能命中（纯静态文件命中不了），
而 `/games.html` 这种真实存在的文件会先被静态分支直接交给 Web 服务器，两条路径内容一致。
`src/` 与 `database/` 依旧在 Web 根目录之外，加多少个页面都不会让它们暴露。

`/manifest.webmanifest` 是个例外：它不在这张表里，也不对应任何真实文件，
由 `public/index.php` 里的 `serve_manifest()` 现生成——原因写在下面「做成可安装的 PWA」一节。

前端脚本也拆成了两层：`core.js` 放几个页面都要用的东西
（`api()`、`el()`、提示条、两段式确认，以及 `SMOKE_TESTS` 这个规则自测登记表），
`app.js`、`games.js`、`arcade.js`、`physics.js`、`study.js`、`reader.js`、`software.js` 各管自己的页面。
抽这一层不是为了好看——`api()` 一旦写两份，改超时、改错误处理时必然漏掉一个。

### 首页的背景光束与入场动画

打开首页直接就是首屏，中间没有全屏的过场层（原来那个「欢迎回来」打字机已经按需要移除了）。

首页底下那一层「两束光穿过玻璃三棱镜、再散成一道彩虹」是 `fx.js` 用 Canvas 2D 手写的，
没有引任何动画库或 CDN —— 既是守住 CSP 的 `script-src 'self'`，也保证离线照样跑得动。

三个实现上的取舍记在这里：

- 光的辉光不靠 `shadowBlur`，而是同一条光叠三笔不同宽度的渐变（26px / 7px / 1.8px）。
  `shadowBlur` 每一帧都要做一次高斯模糊，整屏尺寸下会直接掉帧。
- `devicePixelRatio` 上限截到 1.75，且 `visibilitychange` 时停掉 `requestAnimationFrame`；
  标签页切到后台还满帧重绘是最典型的白耗电。
- 往下滚时背景整体压暗（`updateDim()`），光束退到后面，不和正文抢眼睛。

文字的动画分两套：首屏用**遮罩上升**（`.mask` 裁切 + `.mask-line` 从下面 115% 处升起，
配合 `blur()` 收焦，效果是「字从一条看不见的边缘里长出来」）；下面各区块用
**滚进视口才入场**（`[data-reveal]` + `IntersectionObserver`，同一个区块里按 `--i` 错开 90ms）。
首屏走的是 CSS `@keyframes` 而不是「等 JS 挂 class 的 transition」：它该在页面一打开时自己跑，
不需要任何人来触发，禁用 JavaScript 也照样成立——正因为这样，`fx.js` 里不需要任何补帧的把戏。

按钮那类带投影的元素用 `.rise`（整块上浮）而不是 `.mask`：`.mask` 的 `overflow:hidden`
会把光晕投影裁掉，而动画挂在按钮自己身上又会和它悬停时的 `translateY` 打架，所以套一层外层 `div`。

`prefers-reduced-motion: reduce`（系统里关了动画效果）时不走升降与收焦，改成**原地淡入**
（`@keyframes fade-in-only`），滚动入场同理只留 opacity 过渡；光束只画一帧不循环、锚点也不再做平滑滚动。
也就是说这一档下页面仍然会「出现」，只是不再有位移和循环运动。

### 背景是毛玻璃，不是纯色

整站的深色底由三层叠出来，都在 `style.css` 第 1~3 部分：

```
body::after 彩色光晕（CSS 径向渐变，静态）   z-index -3
body::before 淡网格线                        z-index -2
#fx          光束画布（只有首页有）           z-index -1
```

磨砂要看得出来，前提是**背后得有东西可折**，所以每个内容区块 `.board-section`
（首页的我的用量 / 运行状态 / 留言板 / 备忘录，以及 `/games` 的列表区）都是一块真玻璃：
`background: var(--panel-bg)` + `backdrop-filter: blur() saturate() brightness()` + 上沿 1px 内高光 + 软投影。

三个不显然的点：

- `--glass-blur-fx` 里那个 `brightness(0.62)` 不是装饰，是**可读性**：光束芯是纯白的，
  不加这层压暗时正文对比度会掉到 2.5:1；加上之后最差 6.3:1、常态 16.9:1（实测按 WCAG 公式算的）。
- 模糊只打在**面板这一层**。面板里的小卡片（留言条目、备忘条目、指标格）改用
  `--panel-fill` 的薄底 + 内高光，不再各自 `backdrop-filter`：父层已经模糊过了，
  子层再模糊一次看不出差别，却要按像素再算一遍。
- 手机端把 `--glass-blur` 从 18px 降到 10px（`@media (max-width:768px)`），
  并给了 `@supports not (backdrop-filter: …)` 的实色回退——老浏览器上没有模糊，
  半透明底会让文字压在背景上读不清，就干脆换成不透明深底。

### 导航栏的下拉菜单

导航里的「首页」不是一个链接，而是一个 `<button>`（带 `aria-haspopup` 与 `aria-expanded`）：
点它展开「游戏 / 学习 / 留言板 / 备忘录」，桌面端鼠标悬停也会展开，点空白处或按 Esc 收起。
展开状态只改一个 class，动画全交给 CSS ——

```
opacity 0 → 1   ●   translateY(-8px) → 0   ●   scale(0.96) → 1   ●   transform-origin: top center
```

共 220ms，所以是「跳出来」而不是「啪一下出现」。实测逐帧采样确认过：
点击后 opacity 依次是 0.014 → 0.40 → 0.70 → 0.99 → 1，同时 y 从 50 滑到 58。

两个容易踩的坑，代码里都处理了：

- **触发器与菜单之间那道空隙**：鼠标从触发器往下移到菜单的途中会离开 hover 区域，
  菜单一闪就没了。所以给子菜单加了一条 14px 高的**透明「桥」**（`.nav-submenu::before`），
  让这段空隙仍然算在悬浮区域内。
- **鼠标停在触发器上时点它想收起**：此时 CSS 的 `:hover` 仍在生效，
  class 去掉了菜单却还挂在屏幕上，看起来像点了没反应。
  所以点击收起时会临时加一个 `.hover-off` 屏蔽 hover 展开，鼠标移开自动恢复。

### 游戏板块：内容留在数据里，不在代码里

「加一个游戏」不需要改代码，往 `games` 表写一条记录就行：

- **初始内容**（王者荣耀 / 原神）只在表为空时写入；之后一切由接口维护，
  安装脚本与迁移脚本都不会覆盖你改过的数据
- 表结构里把以后会用到的字段一次留好：英文标识（锚点用）、厂商、类型、简介、图标、排序、上下架
- **新增走 `POST /api/admin/games`**，校验完整（长度、必填、唯一标识），
  页面上的表单、以后写的脚本或导入工具都能直接用同一个接口
- 卡片上每个游戏都是一个跳转入口，新标签打开官网，`rel="noopener noreferrer"`
- 管理员在页面上可以**直接添加、上下架、删除**，不必敲 curl

**跳转地址只允许 http / https**。这一条是安全要求，不是洁癖：
这个值会被渲染成 `<a href>`，一旦容许 `javascript:` 之类的伪协议写进来，
点这张卡片就等于在别人浏览器里执行脚本。后端 `validate_game_url()` 卡住它，
前端 `safeUrl()` 再判一次（纵深防御），不合法时降级成纯文本、不生成链接。

### 学习板块与番茄钟（`/study`）

一个专注计时环加一份按账号隔离的记录。三处写法上的选择值得说明：

- **计时不累加刻度，只记截止时刻。** 开始就把 `endAt = Date.now() + 剩余秒数` 算好，
  每次 tick 用 `endAt - Date.now()` 反推剩余。浏览器会把后台标签页的 `setInterval`
  降到每秒一次甚至更慢（合盖、休眠同理），累加刻度的写法会**悄悄少算**——
  看着还在跑，其实时间已经不准了。按截止时刻算就不会，切回来那一刻自动是对的。
- **环上的数字用 `tabular-numeric`（`font-variant-numeric: tabular-nums`）**，
  等宽数字，`24:59 → 24:58` 时宽度不变；默认比例字体下每个数字宽度不同，秒位会左右抖。
- **进度环是手写 SVG，不引任何库。** `stroke-dasharray` 固定成周长（`2πr`，r=52 → 326.73），
  `stroke-dashoffset` 按剩余比例调；CSP 是 `script-src 'self'`，本来也引不进来。

**放弃的轮次也要记**（`finished = 0`，列表里左侧标一道红边），
记录的是「这一段实际坐了多少分钟」，而不是「我是不是赢了这场游戏」——
只记跑完的轮次会让统计一路偏高，越用越不可信。
`elapsed` 允许比计划多出 30 秒（跨过整分钟边界提交），再多就当参数非法拒掉。

### 小游戏：`/games` 里的 2048 与贪吃蛇

上面那些卡片是「通往游戏的门」，这一节是游戏本身。全部逻辑在 `arcade.js` 里，
**一行都不碰后端**——所以没登录能玩、后端没起来也照样在；最高分只写本机 `localStorage`
（读写都包了 `try/catch`：隐私模式下它会直接抛异常，而最高分是锦上添花，不该变成一条错误提示）。

六个不显然的点：

- **规则写成不碰 DOM 的纯函数，随机数由参数注入。** `slideRow2048` / `moveBoard2048` /
  `stepSnake` 都是「给同样的输入必给同样的输出」，所以规则本身可以断言：
  文件末尾的 `smokeSelfTest()` 里三十来条断言测的就是它们（一次移动里每格最多合并一次、
  撞墙不给分也不把身体画进墙里、不允许一格内直接掉头……），前端烟测会调用它。
- **计时策略和番茄钟相反。** 番茄钟按截止时刻反推、切回来自动补齐；
  蛇如果发现自己落后 3 秒就补 20 步，会直接穿到墙上，所以它落后就跳过、一次只走一步。
  同一类代码里放两种相反的写法，是因为「时间准」和「位置准」在这里是冲突的。
- **同一页上的两个方向键消费者不能都挂在 `document` 上。** 一开始贪吃蛇是全局接方向键的，
  结果是：想操作 2048 蛇也跟着拐，而且在页面任何地方按方向键都滚不动了。
  现在棋盘和画布都要先拿到焦点（`tabindex="0"` + `:focus-visible` 焦点框），
  两个游戏规则一致，页面该滚还是能滚。
- **顶层 `const` 在普通 `<script>` 里是共享的全局词法绑定**，不是各文件私有的。
  `arcade.js` 和 `games.js` 服务同一个页面，撞名字不是「覆盖」而是整页 `SyntaxError`，
  所以本文件的顶层名字一律带 `2048` / `Snake` / `arcade` 前缀。
- **`<canvas>` 有两套尺寸**：CSS 决定它显示多大，`width`/`height` 属性决定里面有多少像素可画，
  而画图用的是后者的坐标系。拿显示宽度算格子、却画在 480 宽的底图上，画面会偏到左上角。
  `snakeCellSize()` 每帧把底图对齐到「显示宽度 × `devicePixelRatio`」，并凑成 15 的整数倍，
  格子才是整像素。
- **空格子内联进去会闪一下**：`render2048` 每帧重写 `className`，同一个格子连续两次「新出现」
  时 class 值一模一样，浏览器认为没变化、动画不重播。所以顺序必须是
  「先写成不带 `tile-new` 的 → 读一次 `offsetWidth` 强制回流 → 再加 `tile-new`」。

### 物理沙盒：渐变、3D 与弹球（`/games` 第三个互动区）

第 9 项要的是「渐变、3D、物理」。落点选的是并进 `/games`，而不是再开一个页面：
这一页已经有两份画布代码和一套脚本加载顺序约定，多一个二级页面就要多维护一份路由表、
导航和页脚链接，换来的只是同一批人路过时的三分钟。所以 `/physics` 故意返回 404，
测试里盯着这一条。三种效果各有归处：标题 `.grad-title` 是渐变字，
右侧卡片 `.physics-card` 是 3D 翻面（`perspective` + `preserve-3d` + `backface-visibility: hidden`，
正反两面叠在同一个格子里），画布是重力与碰撞。

逻辑全在 `physics.js`，和另外两个小游戏一样**一行都不碰后端**。七个不显然的点：

- **物理算在 100×60 的「虚拟单位」里，不算在像素上。** 画布底图尺寸每帧跟着
  「显示宽度 × `devicePixelRatio`」走（`physicsScale()`），速度若用像素算，
  换块高 DPI 屏手感就变了、拖大窗口时球会自己加速。渲染时统一过一遍
  `ctx.setTransform(scale, 0, 0, scale, 0, 0)`。代价是 CSS 里 `.physics-canvas`
  的 `aspect-ratio` 必须和 `PHYSICS_W / PHYSICS_H` 严格相等，不然圆会画成椭圆。
- **撞墙反弹要同时看位置和速度方向。** 只判断「越界了就翻速度」，一颗**正在离开**地面的球
  会在下一帧又被判越界、再翻一次，于是被吸在地板上抖。现在四面墙都带
  `if (ball.vx < 0)` 这类方向条件，只有真朝墙走才反弹。
- **速度上限是照「最坏的一步」定的**：`PHYSICS_MAX_SPEED × PHYSICS_STEP < PHYSICS_MIN_RADIUS`，
  保证最小的球一步也跨不过另一个球的半径，不会穿模，也就不需要连续碰撞检测。
- **按住的那颗球 `invMass` 记 0**，等于一堵会移动的墙：碰撞时它参与位置修正但不动自己的速度，
  松手时把跟踪指针得到的速度整份交给它，所以「甩」真甩得出去。质量取 `r²`（面积），
  大球撞小球自然就把它顶开。
- **落后就跳过，不追帧**——和贪吃蛇同一套，和番茄钟相反。固定步长 `1/120` 秒、一帧最多 6 步，
  超了就把积累的时间丢掉。切后台再回来若补上三百步，球会直接穿过墙。
- **渐变字得留退路**：`background-clip: text` 要配 `color: transparent`，
  在不支持它的浏览器里标题会被整个擦成空白，所以外面包了一层
  `@supports not (background-clip: text)` 换回实色。
- **`prefers-reduced-motion` 下沙盒是暂停启动的**（按钮上直接写「继续」），翻面卡片也贴平
  （`transform: none`）。这个开关在部分内嵌浏览器面板里恒为真，「一进来是静止的」不一定是 bug。

同一页上有两套规则自测（`arcadeSelfTest` / `physicsSelfTest`），它们往 `core.js` 里的
`SMOKE_TESTS` 数组登记，而不是都叫 `smokeSelfTest()`：普通 `<script>` 顶层的同名**函数声明**
是静默覆盖，不报错、不 `SyntaxError`，先写的那套从此再也没跑过而测试照样全绿。

### 小说阅读：选中一个 txt，变成一本能读的书（`/read`）

第 10 项「自动识别小说并转小说阅读」的做法是**文件导入**：选中本机一个 txt，浏览器把它读成文本，
站点认出章节结构，按账号存成一本可翻页、记得住进度、读过的章节离线也还在的书。
刻意没有做「填个网址后端去抓」——那要引入 SSRF 与别人站点的正文版权两摊事，
而用户手上真正有的就是一个已经躺在下载目录里的文件。
（这一版最早做的是「粘一大段正文」，换成选文件是因为手机上粘五十万字根本没法操作，而文件就在手机里。）

**为什么不走 `multipart` 上传**：浏览器读文件是一行的事（`FileReader` 拿字节、`TextDecoder` 解码），
接口于是仍然只收 JSON——服务端就此少了三样东西：会落盘的临时文件、要解析的 multipart 边界、
要判定的 MIME 类型。这三样每一项都是攻击面，而它们换来的便利在这里只有一项：省掉一次前端解码。
代价是一份大文件会先在浏览器里占一块内存，
所以 `readByteCeiling()` 按「一个字符最多 4 字节」，把光看字节数就装不下的文件挡在读取之前——
装不装得下是按**书架还剩多少字**算的（`readRemainingChars()`），因为本站对单本没有上限可判。

**接口只收纯文本，但这一道不是杀毒**：`novel_assert_plain_text()` 看的是文件的形状——
开头的 `MZ`（exe / dll）、`PK\x03\x04`（zip，docx / epub / apk 都是它换皮）、`\x1f\x8b`（gzip）、7z、rar、
`\x7fELF`、老版 Office 的 `\xd0\xcf\x11\xe0`、`%PDF`；再加上「正文里有没有 `\0` 字节」和
「头、中、尾三段里不可打印字符是不是超过一成」。浏览器侧的 `readLooksBinary()` 是同一套判断的另一份实现，
图的是**选文件的当下就说**，不用等几十兆传上去才知道这不是文本（两份实现之间靠测试用例里同一批字节对齐）。
它不认识任何病毒，也没有病毒库——真正的防线是结构性的：正文只能作为 JSON 里的一个字符串进来，
服务端从不把它落成文件、从不 exec，回到浏览器时只走 `textContent`。这一道挡的是「往书架堆几十兆没人读得到的二进制垃圾」，
顺带挡住改名成 .txt 的伪装。判断必须排在 `novel_normalize_text()` **前面**：那个函数会删掉控制字符，
先删再验等于把证据擦了再查指纹。

**编码只能在浏览器里认**：中文 txt 有一半不是 UTF-8——GBK / GB18030 是老机器上的主流，
记事本里那个「Unicode」存出来的是带 BOM 的 UTF-16。判断顺序是 BOM → UTF-8 严格解码 → GB18030，
且**只有第一次**带 `{fatal: true}`：不带 fatal 的解码器永远不会失败，
GBK 的字会被它「成功」地换成一片 U+FFFD。这一步挪不到后端——文本一旦以 UTF-8 字符串发出接口，
编码信息就已经丢了，后端再猜是在猜一份已经错掉的文字。
BOM 与不可见字符仍然由 `novel_normalize_text()` 清掉，
所以「UTF-8 带 BOM」和「UTF-8 不带 BOM」两份同样的文件，分章结果一个字都不差。

识别规则全在 `src/novels.php`，前端一行分章规则都没有。理由很实在：规则要能被测试逐条钉住
（`tests/cases/16-novel.php`），而浏览器里的同一份规则永远会在某次改动后和后端不一致——
不一致的表现是「同一本书在手机上和电脑上分得不一样」，这类问题最难查。

认标题的四条判断：

- **形状**：`第X章 / 节 / 回 / 卷 / 篇 / 集 / 幕`、`Chapter 7`，以及`序章 / 楔子 / 引子 / 前言 /
  尾声 / 终章 / 大结局 / 后记 / 番外 / 附录 / 致谢`这类栏目标题。必须**从行首**开始匹配。
- **长度与语气**：整行不超过 40 字，且不以 `。！？，；…` 结尾——「第三章的内容让我想到。」是正文。
- **标题后面得跟着正文**：下一行之前有正文才算一章。文件开头那份**目录**因此整块退回普通文字，
  不会切出几百个空章。这是全套规则里最值钱的一条。
- **纯数字式让位**：`1、xxx` 这种行只在整本没有任何命名式标题时才用（比如流水账笔记），
  有真标题就彻底不作数，免得把一章劈成两半。

书名有三个来源，优先级是**用户填的 > 正文里的书名页 > 文件名**。文件名排最后是有意的：
下载站给文件起的名字（「某某全文无删减.txt」）不该盖过书本身写着什么，
只有正文里什么都猜不出来时它才上场（`novel_title_from_file()`：只剥得动 txt / md 这类纯文本扩展名，
再长的名字也只截断、不报错——兜底不该把一次本来能成的导入掀掉）。

三件不显然的实现：

- **一章一行存进 `novel_chapters`**，而不是一整块 `LONGTEXT`。翻页才能按章取（开书接口只回目录，
  正文一个字节都不送），目录上每章的字数、超长章的切分、删书时的级联清理都直接是行操作。
  代价是要维护 `(novel_id, seq)`；导入时在一个事务里把**同一条**预处理语句逐章 `execute`，
  一次往返一章，整本书从不拼进一条语句——所以 MySQL 的 `max_allowed_packet` 只需要容得下最大的一章
  （受 `novel_chapter_max_chars` 管），跟全书多大无关。
- **进度存「第几段」而不是滚动比例。** 比例在换设备、改字号、换屏幕时全都会变，段落序号不会。
  章号 + 段号也够小、够好校验（越界一律 422，`seq=-1` 取章是 404 而不是被夹成第 0 章）。
- **离线副本存 `localStorage`，不交给 Service Worker。** SW 的缓存键是 URL，而这些正文是**按账号**
  隔离的私有内容，缓存住接口等于缓存住别人的登录态——所以 `sw.js` 明确放过 `/api/`。
  换法是按章往本机存一份副本，装满了按「离当前章由近到远」淘汰（`readCacheKeep()`），
  断网时取章失败就直接渲染副本并写明「这一章来自本机副本（离线可读）」，删书时那份副本一起清掉。

上限可以在配置里调：`novel_max_count` 30 本、`novel_max_total_chars` 5000 万字（一个账号书架上的总量，
正文约 150 MB）、`novel_chapter_max_chars` 3 万字、`novel_max_chapters` 5000，另有 `novel_min_chars` 200
用来挡误触。**单次导入没有字数上限**——一本连载完的长篇就是三五百万字，按「一次能塞多少」设上限
等于把真实需求挡在门外；改成按账号总量算之后，磁盘的边界还在，却永远碰不到正常读书的人。
总量算的是**此刻还留在书架上的字数**（`SUM(char_count)`），删掉一本就退还原来的额度，
所以拒绝的话术里直接写着「删掉不再读的几本就能继续导」。
`novel_max_chapters` 卡在 `seq` 与 `chapter_count` 两列的天花板（SMALLINT 最大 65535）之下，
超了是一次说清楚的 422，而不是数据库报 out of range——它挡的是「每行都像个标题」那种病态输入。
上限随 `GET /api/novels` 一起下发，前端不抄一份常量。测试环境用环境变量把这几个数压小，
几秒钟就能把每条「拒绝」分支真跑一遍。

正文**不做转义也不去标签**：那是用户自己的小说，库里就该是他那个文件的一份原文；
「文件里的内容不许变成代码」这件事全压在渲染侧——`reader.js` 只用 `createElement` + `textContent`
建节点，一次 `innerHTML` 都没有，加上 CSP 的 `script-src 'self'` 兜底。
`tests/cases/16-novel.php` 里那条「带 `<img onerror>` 的正文原样返回」就是钉这一对的。

浏览器实测时量到一个纯靠读代码看不出来的点：跳回上次那段时，`window.scrollTo()` 收的是取整后的
坐标，而段落自己的 `getBoundingClientRect()` 是小数，段落顶边会落在「阅读线」下方零点几像素处，
于是下一次存进度判定成上一段——表现出来就是「每次接着读都往前退一段」。
`jumpToParagraph()` 因此多滚 1px，测试里钉了一行防止被当成多余代码删掉。

2026-09-23 改成文件导入之后，同一本书做了三份编码不同的文件——**UTF-8 带 BOM、GB18030、
带 BOM 的 UTF-16LE**——在真浏览器里各导一次，三次都是 5 章 344 字，
页面上分别写着「按 utf-8 / gb18030 / utf-16le 读的」，GB18030 那一份的书名仍然是从正文里的
`《雾中灯塔》` 认出来的（不是文件名）。编码这条路只能在浏览器里验：`TextDecoder` 是它的活，
PHP 侧的用例拿到的是已经解好的字符串，看不出解错过没错过。

2026-09-23 拿掉「单次 50 万字」这道上限之前，先量了两件光读代码量不出来的事。

一是**这条管道扛不扛得动整本书**。一份 16 MB / 570 万字的正文走完 `novel_normalize_text()` →
`explode` → `novel_scan_chapters()` → `novel_split_oversized()` 全程 228 ms、峰值内存 80 MB；
18 MB 的请求体 `json_decode` 是 98 ms、峰值 40 MB。`memory_limit` 256M、`max_execution_time` 0，
插库是一章一次往返（见上面那条），`max_allowed_packet` 64MB 只要容得下一章——真实数量级上没有一个环节是瓶颈。
然后在真浏览器里导了一本 8.9 MB / 294.6 万字 / 1200 章的书：目录 1201 行（前言 + 1200 章），
开书接口一个正文字节都不送，从目录跳到第 600 章取到 68 段，末章 `hasNext` 为假、越界一章 404，
删掉它之后「已用 xxx 字」跟着退回原样——配额按「还在书架上」算这件事只有在真删的时候才看得见。

二是**这类请求到底会怎么死**。`post_max_size` 并**不会**截短 `application/json` 的请求体：
把它调成 8M 再用 18 MB 的正文打进去，`php://input` 一个字节不少地到了服务端，`json_decode` 也照样成功
（只有 `$_POST` 是空的，而本站不读它）。可是超限那条 `Warning: POST Content-Length ... exceeds the limit`
在 `display_errors=1` 下会印在 JSON **前面**——于是接口其实已经把书存进去了，响应却是一坨解析不了的文本。
用户看到的是「导入失败」，书架上多了一本书，再点一次又多一本。**放开大文件之前，先确保 `display_errors` 是关的**
（这一条在 `deploy/CHECKLIST.md` 里也钉着）。

### 软件仓库：收录一款工具，安装包由服务器代下载（`/software`）

第 11 项「仿照图片新增板块」的产物。左边一栏按分类分组并带上每类的数量，右边是卡片：
图标（没有本地图标时显示首字母）、软件名 + ★、分类徽章、`#标签`、支持的平台、两行简介、
`v0.19.1 · MIT · 11.7 MB` 这一行元信息，以及 GitHub / 官网 / 下载三个按钮。
上方是平台与标签两套 chip（chip 后面的数由后端一次算好）、一个搜索框、
排序下拉（含「按标签分组」）与网格 / 列表切换。

访客那份清单**永远只含已上架的**（`GET /api/software`），下架条目只有管理员那份
（`GET /api/admin/software`）看得到 —— 和 `/api/games` 是同一套约定：结果不随调用者身份变化，
缓存、排障和测试才不用考虑「谁在打这个接口」。

**「服务器代下载」是本站第一次由服务器主动出网**，所以这一板块真正的功能其实是那道闸
（`src/softnet.php`，一个不依赖 curl 扩展的 socket HTTP/1.1 客户端）：

- 只认 `http` / `https`，主机名必须在 `soft_fetch_hosts` 白名单里；比的是解析之前的主机名，
  所以 `http://api.github.com.evil.test/` 这种外壳骗不过去。
- 域名先解析成 IP，落在内网 / 回环 / 链路本地 / 组播段就直接拒 —— 挡的是「白名单域名被 DNS 指到内网」
  和「路由器管理口」这两类。`soft_fetch_allow_private` 只为测试留一条活路（本机假源站），
  生产必须保持 `false`，`database/doctor.php` 与安全提示会盯着它。
- 每一跳重定向都重新把上面两条走一遍（GitHub 的下载本来就换域名，跳过白名单等于没闸）。
- TLS 校验开着：下载下来的是要发给访客的安装包，中间人换包等于投毒。
- 边下边数，超过 `soft_max_file_bytes` 立刻中断并删掉 `.part`；全部安装包合计还要过 `soft_quota_bytes` 这一道。
- 扩展名白名单 + 按文件头认内容：`.md` / `.txt` / `.php` / `.html` / `.js` / `.svg` 这类文本、脚本、网页一律不收。
  放一个 HTML 进来，浏览器点开它就是在本站域名下跑别人的脚本。
- 落盘文件名先经 `softnet_safe_name()` 洗过（目录穿越、控制字符、超长都砍），最终一律叫 `id.扩展名`；
  这个目录在 `var/` 下、Web 根之外，只能经 `/api/software/file?id=` 发出去 —— 每一次下载都要再判断一遍
  「上架了吗、包真的在吗」。
- **抓失败什么都不改**：库里那条还是旧记录，磁盘上不留半成品，界面上一句「为什么没抓到」。

三道大小闸各管各的，别把它们混成一条：

| 配置键 | 默认 | 环境变量 | 挡什么 |
| --- | --- | --- | --- |
| `soft_fetch_enabled` | `true` | `WEB_ONE_SOFT_FETCH_ENABLED` | 出网总开关。关掉之后识别、抓包、抓图标三个动作一律拒绝，列表和已经落盘的包照常可用 |
| `soft_fetch_hosts` | GitHub / Gitee 那几个域名 | `WEB_ONE_SOFT_FETCH_HOSTS` | 允许出网的主机白名单，加源站改这一行就够，不用动代码 |
| `soft_fetch_timeout` | 20 秒 | `WEB_ONE_SOFT_FETCH_TIMEOUT` | **建连与两次读之间**的间隔，不是整条请求的总时长 |
| `soft_fetch_max_redirect` | 3 | `WEB_ONE_SOFT_FETCH_MAX_REDIRECT` | 最多跟几跳 |
| `soft_fetch_meta_bytes` | 300 KB | `WEB_ONE_SOFT_FETCH_META_BYTES` | 仓库元数据的响应体上限（识别用不到这么多，防的是拿一个 GB 的 JSON 撑内存） |
| `soft_icon_max_bytes` | 200 KB | `WEB_ONE_SOFT_ICON_MAX_BYTES` | 单个图标上限，超了当没抓到 |
| `soft_max_file_bytes` | 200 MB | `WEB_ONE_SOFT_MAX_FILE_BYTES` | 单个安装包 |
| `soft_quota_bytes` | 2 GB | `WEB_ONE_SOFT_QUOTA_BYTES` | 全部安装包的总占用 |
| `soft_max_count` | 300 | `WEB_ONE_SOFT_MAX_COUNT` | 这张表最多收录多少款 |
| `soft_fetch_allow_private` | `false` | `WEB_ONE_SOFT_FETCH_ALLOW_PRIVATE` | 只给测试用；生产开着它等于把内网交给这条链路 |

**「自动识别信息」与「智能获取图标」只读不写。** 识别回来的是 `version`、`starCount`、`license`、
`description`、`homepage` 五格，填进表单等管理员核对后再保存 —— 认错了来源也不至于把库改脏
（`POST /api/admin/software/identify`）。来源顺序是 GitHub → Gitee，一家都报不出结果时，
把「试过谁、各自为什么不行」一起回成一句，而不是只说「失败」。仓库 API 的地址由 `software_repo_api()` 拼，
测试白名单里没有 `api.github.com`，所以字段解析这一层由 `software_repo_json` / `software_repo_meta` /
`software_release_version` / `software_identify_one` 直接打假源站验（`tests/fake_http.php`）。

**这类请求比别的接口慢得多，两头都要放宽。** 前端对抓包、识别、抓图标三个动作用的是
`CORE.slowApiTimeout`（120 秒），不是默认的 5 秒；反代那边 —— nginx 的 `fastcgi_read_timeout`
（本站是 `fastcgi_pass`，不是 `proxy_pass`，`deploy/nginx.conf.example` 里已从 30s 提到 180s）、
PHP-FPM 的 `request_terminate_timeout`、以及云负载均衡的空闲超时 —— 默认常常只有 30 到 60 秒，
会先于服务器断：那一发看到的是网关的一页 504 而不是一段 JSON，界面上说不出这次抓到了哪一步。
让浏览器的 120 秒先到才有意义 —— 超时之后刷新一下，「大小 / 抓取时间」变没变就是这一次成没成，
因为落盘的顺序是先写文件、成功后才写库。

**PHP 自己也有一刀，而且 Windows 上那一刀更利。** `max_execution_time` 在 Linux 上只算 CPU 时间
（等网络不计时），在 Windows 上算的是**墙上时间** —— 实测把它调成 2 秒、再跑一个纯 `sleep()` 的八秒循环，
会被 `Maximum execution time exceeded` 杀掉；同一个循环里每轮补一句 `set_time_limit()` 就跑得完。
所以 `SoftnetConn::fill()` 每从 socket 读到一次数据，就把这道时限往前拨一次，
拨的是 `max(30, 2 × soft_fetch_timeout)` 秒。于是：一直在传字节的慢请求不会被 PHP 掐掉，
而卡住的连接仍然由 `stream_set_timeout` 判成「等待远端响应超时」——
那个数刻意只有它的一半，为的是让**说得清原因的那一刀先落**。
这一条只能钉源码（`tests/cases/17-software.php` 里现读 `src/softnet.php` 的 `fill()` 函数体），
因为用例都跑在默认 30 秒之下、每次抓包几百毫秒就结束，删掉那句续命不会有任何 HTTP 断言变红。

**配额那一行只有管理员看得到。** `quota`（已用字节 / 包数 / 上限）只出现在 `GET /api/admin/software` 里，
访客与普通账号的响应根本没有这个字段。这和「运行状态」「我的用量」是同一道边界：
各人自己那份用量对本人放开，全服务器共用的资源数字只给管理员 ——
所以这一页刻意没有为了「让访客也看到剩余空间」去开一个只读的公开口子。

> 实测记下来的一件事：这台开发机上 `github.com` 的 archive 地址连不通（TCP 建连超时），
> 而 `api.github.com`、`codeload.github.com`、`avatars.githubusercontent.com` 都通。
> 于是同一次操作里「识别信息」和「智能获取图标」都成功，只有抓 `tar.gz` 那一步报连接失败。
> `softnet_connect()` 因此在 TLS 失败时把底层那句警告一起带出来（IP 不打进界面），
> 免得照着「证书校验未通过」这条线索去查 CA —— 真正的原因常常是网络不通。

### 做成可安装的 PWA（手机 / 车机上的「客户端」）

第 8 项「变成客户端 / 车机端」选的是 PWA 这条路，而不是 Electron / Tauri 那种套壳：
同一个站点、同一份后端，装完有独立图标和独立窗口，不需要再维护一套桌面工程，
也不给仓库添一个几十 MB 的产物。代价是它仍然要求设备能访问到这个地址（见下面的前提）。

四个新文件各管一件事：

| 文件 | 干什么 |
| --- | --- |
| `/manifest.webmanifest` | 应用清单：名字、图标、启动地址、窗口形态。**由 `serve_manifest()` 现生成** |
| `public/sw.js` | Service Worker：把访问过的页面与资源存一份，断网时拿出来 |
| `public/offline.html` | 兜底页：断网且缓存里也没有这一页时看到的东西 |
| `public/assets/js/pwa.js` | 注册 SW；浏览器认为可安装时才在页脚插一个「安装到桌面」按钮 |

四个不显然的决定：

- **清单为什么是 PHP 生成的**：浏览器按 `Content-Type` 决定要不要读它，而
  `.webmanifest` 在 PHP 内置服务器和老 Apache 的扩展名表里常常没有对应项，
  本地能装、线上装不上是最难查的一类差异；再加上 `.htaccess` 与
  `nginx.conf.example` 都把 `public/` 下的 `*.json` 一律拒下载（防误放配置文件），
  放一个真实的 `manifest.json` 会被那条规则挡住。现生成一次解决三件事，
  顺带让名字和主题色只有一处定义。旧地址 `/manifest.json` 仍然返回同一份内容，
  已经装上的应用不会掉清单。
- **一律「先网络，不通才翻缓存」，不用缓存优先。** 这个站的 CSS / JS 是固定文件名
  （`/assets/css/style.css`，没有内容指纹），缓存优先会让改过样式的用户一直看到旧页面，
  而且看不出为什么。四个页面加几个脚本的量走网络几乎不花时间，
  用一点速度换「刷新看到的一定是最新的」值得。
- **`sw.js` 必须放在站点根**。Service Worker 的可控范围由它自己的 URL 决定，
  放进 `/assets/js/` 就只能管那个目录，`/games` 离线打不开——而且不报错。
- **离线页必须自包含**：样式全写在文件里，不引 `/assets/`，也没有任何脚本
  （CSP 是 `script-src 'self'`，内联 `onclick` 会被拦掉，所以「重试」是一个普通链接）。
  它是在「什么都拉不到」的时刻才被拿出来的，引用外部资源等于让它变成一张白页。

**前提是 HTTPS。** 浏览器只在安全上下文里允许注册 SW：`https://` 或者
`http://localhost` / `http://127.0.0.1`（所以本地开发直接就能试出安装效果）。
局域网里的车机要用手机热点那种 `http://192.168.x.x` 访问时，这一整块会静默不生效——
`pwa.js` 里注册失败是不弹提示的，因为离线本来就是加分项。上线步骤在
`deploy/CHECKLIST.md` 里。

### 前端启动烟测（`tests/js-smoke.js`）

HTTP 用例只能证明后端答得对，证明不了页面脚本跑起来了。
2026-09-22 `study.js` 里把一个变量名写错（`pomo` / `pomoState`），
`boot()` 在第一次渲染就抛 `ReferenceError` 中断，页面留下的是 HTML 里的初始文字，
看着像「加载完成」，当时 558 条断言一条没红。

于是有了这个文件：用正则把 `<page>.html` 的 id / class / `data-*` / `value` 扫成一份假 DOM
（`getElementById` 取不到就返回 null，和浏览器一致），
再按页面里 `<script src>` 的顺序把脚本喂给 `vm` 跑一遍。三类问题会被点名：
脚本抛出的异常（带文件名和行号）、JS 要的元素在 HTML 里根本不存在、
以及同页脚本撞了顶层名字（第二个脚本求值时直接 `SyntaxError`）。
`php tests/run.php` 会顺带跑它；机器上没有 node 时它自己跳过，不算失败。

页面脚本还可以往 `core.js` 的 `SMOKE_TESTS` 数组里登记纯规则自测函数（目前登记了五组：
`core.js` 的 `coreSelfTest` 测共用格式、`app.js` 的 `appSelfTest`、`reader.js` 的 `readerSelfTest`、
`arcade.js` 与 `physics.js` 各一组，合计七十余条断言），烟测跑完这一页的脚本后会逐个调用它们。
之所以是数组而不是一个约定好的 `smokeSelfTest()`：同一页上的两个脚本都定义同名函数时，
后者**静默覆盖**前者，不报错也不 `SyntaxError`，先写那套断言就永远不跑了，而测试仍然全绿。
没登记任何函数不算失败，但烟测会打印「规则自测跑过的页面：页名（a、b、c）」，
`tests/cases/12-js-smoke.php` 把这一行按页名拆开、逐个比对完整清单——
**登记了却从没被调到**的自测等于死代码，那才是最需要它跑起来的时候；
少一组、多一组、甚至在某一页上换成了别的组，都会被这行断言点出来。

## 资源监控（不需要任何插件）

管理员登录后，首页首屏下面就有**「运行状态」**一节：内存、请求耗时、缓冲池命中率、
MySQL 连接数、各磁盘使用率几张卡片加两条趋势折线常驻显示，点「查看完整面板」
（或导航栏的「系统状态」）展开含条形图与诊断结论的完整面板。
两处读的是同一个 `GET /api/admin/system`，卡片清单也只有一处定义
（`sysCardItems()`，标了 `home` 的那些出现在首页），不会出现「弹窗有、首页没有」。

**这一节的边界**：它报的是**这台服务器**跑得怎么样。内存、磁盘、连接数、各表行数
这些数是全机共用的，不属于任何一个账号，所以只对管理员显示——
`GET /api/admin/system` 里有 `require_admin()`，普通账号和游客拿到的都是 403。
每个人想看的那份「我的性能」不住在这里，住在紧邻它上面的**「我的用量」**那一节，
见下一节。

它的全部数据来自四类**原生能力**：

| 来源 | 拿到什么 |
| --- | --- |
| PHP 内存函数 | 进程占用 / 峰值 / `memory_limit` 占比、本次请求耗时、已包含文件数 |
| `disk_free_space()` / `disk_total_space()` | 各磁盘的总量、剩余、使用率（Windows 与 Linux 都可用） |
| `SHOW GLOBAL STATUS` | 运行时长、查询数 / QPS、慢查询、线程、临时表落盘、连接与中止、收发字节、InnoDB 缓冲池命中率 |
| `performance_schema` / `information_schema` | MySQL 服务端**按组件的内存分布**、各表占用空间与行数 |

外加一张由历史采样画出来的趋势图（PHP 进程内存 / 请求耗时 / 单次请求的 SQL 条数），
以及一组「说人话」的诊断结论——每条都写清了现象、含义和该做什么。

**为什么不去读操作系统的整体内存和 CPU**：Windows 上那条路要走 `wmic`，
而它在本机已被安全策略拉黑；更重要的是，一旦依赖平台命令，这套代码就绑死在 Windows 上了。
上面四类换到 Linux 同样能跑，`doctor.php` 也会顺带检查这些数据源是否可用。
真要 OS 级的曲线，交给 Prometheus + node_exporter 这类专门的监控栈更合适——
这个面板负责的是「应用自己这一层」，而那恰恰是排障时最常需要的一层。

**采样是怎么记的**：每次打开面板、以及每次页面访问（`POST /api/visit`）都会尝试记一条，
但两次采样之间有最小间隔（`stats_sample_interval`，默认 60 秒），且**先判断再采集**——
否则光是「发现还没到时间」就要白跑十来条 SQL。
采样写成 NDJSON（一行一条）追加到 `var/stats/samples.ndjson`，追加写不需要读-改-写，
也就不会因为并发把文件写坏；攒到两倍上限才裁剪一次。

## 我的用量（人人看自己那一份，不用登后台）

首页「运行状态」上面那一节，**任何状态都在**：游客、普通账号、管理员看到的是同一节，
但里面只有**和你自己有关**的数。五张卡的来源：

| 卡片 | 数从哪来 | 谁能看到 |
| --- | --- | --- |
| 你的备忘录 | `GET /api/memos` 的 `stats`（首页本来就要发这一次，不重复请求） | 登录账号 |
| 你的书架 | `GET /api/novels` 的 `stats`（已用字数 / 配额，字数按「多少万字」说） | 登录账号 |
| 你专注的时间 | `GET /api/study` 的 `stats`（分钟数、今天几轮、跑完几轮） | 登录账号 |
| 首屏就绪 | 浏览器 `performance` 的 navigation 条目，从开始导航到 DOM 可用 | 所有人，含游客 |
| 接口往返 | 本页已发出的 `/api/` 请求里最慢的一次 | 所有人，含游客 |

游客只剩后面两张纯耗时的卡，而且这一节**一个请求都不发**——书架是私有数据，
没有「谁的」可言；与其为它做一个公开版统计接口，不如什么都不显示。「重新读取」按钮
也一并藏掉，它没有可刷新的东西。退出登录不需要刷新页面，前三张卡就地消失，
不会把上一个人的数字留在屏幕上。

**这一节没有带来任何新接口**：三张账号卡的数全部来自各自板块本来就在调的那一次请求。
这条边界由 `tests/cases/09-system.php` 钉住——扫路由表（不许多出 `/api/system`、`/api/usage`、
`/api/metrics`、`/api/stats`、`/api/monitor` 这类公开读接口）、扫 `app.js` 里那一段（不许碰
`admin/system`）、扫五张卡的标签（不许出现内存 / 磁盘 / 缓冲池 / 连接 / 慢查询 / 峰值 / SQL / 表），
外加真发请求验证跨账号隔离：甲导入一本书之后，乙的卡上仍然是 0 本 0 字。

## 这一版做了什么

在原有的注册 / 登录 / 后台基础上补齐并优化：

- **安全**：登录失败限流（账号 + IP）、每用户会话数上限、修改密码、安全响应头（CSP 等）、
  同源校验、结构化日志与请求 ID、密码强度额外校验
- **功能**：邮箱验证、找回密码与令牌重置、个人中心、后台分页与搜索、
  后台重置用户密码、访问统计区分 PV / UV、近 7 天趋势
- **留言板与备忘录**（这两个都不需要外部服务，纯站内功能）：
  留言板读公开写要登录、发帖限流、作者或管理员可删；
  备忘录按账号隔离、支持完成勾选与行内编辑、有每账号条数上限
- **游戏板块（二级页面 `/games`）**：导航栏「首页」是一个下拉菜单，
  点它（桌面端鼠标悬停也行）动画展开「游戏 / 学习 / 阅读 / 软件 / 留言板 / 备忘录」，点哪个去哪个；
  收录王者荣耀与原神，每张卡片跳转到官网；管理员可在页面上直接添加、上下架、删除，
  背后的 `POST /api/admin/games` 就是预留好的添加入口
- **学习板块与番茄钟（二级页面 `/study`）**：手写 SVG 进度环 + 按截止时刻计算的计时器，
  跑完和半途中断的轮次都会记进 `pomodoros`（按账号隔离），另有今日/累计专注分钟数
- **小说阅读（二级页面 `/read`）**：选中本机一个 txt，浏览器按 UTF-8 / UTF-16 / GB18030 解码后送给接口，
  后端认出章节结构存成一本按账号隔离的书，猜不出书名时用文件名兜底；**单本不限字数**（几百万字的整本书一次就能导），

这一轮测试还抓出并修掉了几个真实缺陷：

1. **中文邮件主题没有编码**：只做了头部净化、漏了 RFC 2047 编码，
   本地日志里看着正常、真实邮箱里是乱码
2. **「踢掉最旧的会话」顺序不确定**：`created_at` 只精确到秒，
   同一秒内的多次登录排不出先后，实际是随机踢一个；改成按自增 `id` 排序
3. **弱密码会白白烧掉重置链接**：校验密码在消费令牌之后，
   用户输了个不合规的密码就得重新去收一封邮件
4. **未登录时发布按钮被禁用**：用户点不动、也得不到「为什么不给发」的提示；
   改成按钮保持可点，点了直接提示原因并打开登录框
5. **公开接口的结果随身份变化**：`GET /api/games` 原本会被管理员的 Cookie 影响，
   多返回「已下架」的条目。公开接口就应该是公开的那一份，
   否则缓存、排障和测试都不可预期；管理员要看全部走 `/api/admin/games`
6. **接口层把越界参数夹成了合法值**：`minutes` 取参时按上限夹到 180，
   于是 `181` 变成 `180` 顺利入库，校验器根本看不到真实输入。
   改成取整个整数范围、只由校验器判定，测试里那条「181 必须回 422」才真的有意义
7. **学习页脚本有个写错的变量名**：`boot()` 第一次渲染就抛 `ReferenceError` 中断，
   页面留下 HTML 初始文字看着像正常加载，558 条断言全绿。
   修掉变量名的同时补了 `tests/js-smoke.js`，把这类错误也纳入 `php tests/run.php`
8. **同一页上两个方向键消费者打架**：贪吃蛇的键盘监听一开始挂在 `document` 上，
   结果是按一次方向键 2048 和蛇同时动、页面还滚不动了。
   这个**只有在浏览器里真玩一遍**才看得出来——烟测能证明脚本跑起来了，
   证明不了「两个人抢同一组键」；现在两边都要求先拿到焦点
9. **「接着读」会把进度往回退一段**：跳回上次那段时 `scrollTo()` 用的是取整坐标，
   段落的 rect 却是小数，段落顶边落在阅读线下方零点几像素处，下一次存进度就判定成上一段。
   同样只有真在浏览器里读一遍才发现：库里存的是 1，页面也看着停在第 2 段，
   但一滚就写回 0。现在 `jumpToParagraph()` 多滚 1px，测试钉了那一行
10. **被拒过一次之后，红字会盖在正常文件上**：选文件成功的那条路径从不清 `#import-tip`，
    于是一份改名成 .txt 的 zip 被拦下之后，再选一份正常小说，字数和文件名都更新了，
    上面那行「这不是小说正文」还挂着——用户只能以为依然没过。
    现在换文件的第一步就是把上一条结论作废，而且**擦在分支之前**（测试钉住这个顺序）。
    这个也是只有真在浏览器里连着选两份文件才看得出来
11. **文档里的数字会自己变成假话**：这一版拿掉单次字数上限后，翻出来三处已经说错的话——
    nginx 的 `client_max_body_size 4m` 是按「单本 50 万字」算的，几百万字的书会在 nginx 那里吃到一页 413；
    CHECKLIST 写着「`post_max_size` 出厂默认 8M 够用」，而实测 8M 会让一次**已经成功**的导入看起来像失败；
    两处正文与清单说插章节是「一条批量 INSERT」，代码其实是 prepare 一次、逐章 `execute`，
    照着旧说明去判断 `max_allowed_packet` 会得出相反的结论（真正要担心的是 `memory_limit`）
12. **粘来的是 clone 地址，识别就必然 404**：管理员填 GitHub 仓库地址时常常直接抄
    `https://github.com/owner/repo.git`，那个 `.git` 会跟着落进路径第二段，
    拼出来的接口地址成了 `/repos/owner/repo.git` —— 远端回 404，界面上一句「没识别出来」。
    现在 `software_repo_path()` 把结尾的 `.git` 去掉，测试钉了这条
13. **「证书校验未通过」是一句会带错方向的话**：`github.com` 的 archive 地址在这台机器上连不通
    （TCP 建连超时），报出来的却是「证书校验未通过或对方不支持 TLS」，照着这句话会去查 CA。
    `softnet_connect()` 现在把底层那句警告一起带出来（只留 IP 不打进界面），
    分清「连不上」和「证书不对」
14. **`starCount` 只进得来、出不去**：「自动识别信息」认回来的 star 数没有能写入的字段，
    表单填好了点保存就丢掉。补了 `software_star_count()` 校验（负数与小数 422，
    留空是「不知道」而不是 0）并接进新增 / 修改两条路径

## 还没做的

真上线前必须补上这些，`deploy/CHECKLIST.md` 里有逐条的操作方法：

- `root/root` 是可猜到的口令；限流能减缓暴力尝试，但**没有验证码**，分布式撞库仍然难挡
- 部署到 HTTP 下 Cookie 与密码在网络上裸奔（配好 HTTPS 后把 `cookie_secure` 打开）
- 邮箱验证是「发了信就完事」，没有强制未验证用户不能做某些事
- 删除用户是硬删除，没有回收站；管理员账号既不可删也不允许被别人重置密码
- 用户名依赖 MySQL 的大小写不敏感排序规则：`Alice` 与 `alice` 是同一个账号，这是有意的
- `visits` 表每次访问插一行，会随流量无限增长，需要按 CHECKLIST 的建议定期汇总或清理
- 留言板只有「发」和「删」：不能编辑、没有举报与审核队列，管理员只能逐条删除
- 备忘录一次把该账号的全部记录返回给前端，没有分页；每账号 200 条的上限是唯一的保护
- 游戏板块一次返回全部条目，没有分页（它是人工维护的短名单，不是用户内容）；
  也没有封面图上传，图标只能用 emoji
- 番茄钟的列表同样一次全返回（上限 2000 条），且只有「今天」和「累计」两个聚合数字，
  没有按天/按科目的报表；计时器跑在浏览器里，关掉页面这一轮就停了（保存的是已用秒数，
  不是「后台继续计时」）
- 两个小游戏完全跑在浏览器里：没有排行榜、没有存档（刷新就重开一局，最高分留在本机
  `localStorage`，换浏览器或清缓存就清零），也不防改分——想防只要把它们挪到后端做判定。
  贪吃蛇只支持键盘和小键盘按钮，没有触屏滑动操作；2048 没有撤销（一步走错就错了）
- 物理沙盒只能靠指针玩：按住球拖、松手甩，没有键盘入口（方向键已经被两个小游戏抢过，
  刻意不再加）。画布上的 `touch-action: none` 意味着**手指落在画布里就是抓球、不再是滚页**，
  手机上要从画布外面滚过去；最多 26 颗球，球和滑块参数都不保存，刷新回到默认那 7 颗。
  碰撞只做圆-圆：没有旋转、没有滚动摩擦模型，球也不会自己转
- 小说阅读只做到「选一个 txt，能读」这一层：**只吃纯文本**——docx / epub / mobi 都不认，
  而且**认的是文件头，不是病毒**：改名成 .txt 的 exe 会被拒，真带毒的 txt 它一句都看不出来（原因见上面那一节，
  防线是不落盘、不 exec，不是扫描）。繁体常用的 Big5 也不在解码名单里（只试 UTF-8、带 BOM 的 UTF-16、GB18030），
  认不出时会明说一句「另存为 UTF-8」而不是硬猜；**不能改正文、不能手动增删章、没有书签和高亮**，
  改名是唯一能编辑的字段；识别只认中文常见的标题写法，英文里 `Part One`、`IX.` 这类不进名单
  （加一条正则很容易，难的是加了之后每本旧书的分章都会变）。一次导入是**一次性**的：
  再选一次同一个文件是一整本新书，不会跟旧的那本合并。文件是整个读进浏览器内存的，
  所以只有「光看字节数就知道书架装不下」的会被提前挡掉，卡在这个门槛以内的要先占一块内存才知道装不装得下。
  配额本身也**只算字数**：一个账号狂灌 30 本百万字的书，先撞上的是本数上限而不是 150 MB。
  全文搜索、按字数分页以外的排版控制（字体、行距、页边距）也都没有
- 软件仓库只做到「收录 + 代下载」这一层：**分类是自由文本**，没有受控词表，
  靠表单里的 `datalist` 提示复用同一个写法（侧栏才不会裂成「系统工具」和「系统 工具」）；
  **安装包不扫描、不校验能不能跑**，闸门只管类型与大小，一个合法的 zip 里装什么它不知道；
  抓回来的包**不会定期复检**，远端换包、删包都只体现在这一份静态副本上（这正是代下载的目的，
  但也意味着本站要一直背着它）；**没有分页**，300 款一次全返回（它是人工维护的短名单，不是用户内容）；
  「自动识别信息」只认 GitHub / Gitee 两家的仓库 API 与 `releases/latest`，
  没有 release 只有 tag 的仓库认不出版本号，得手工填那一格
- 二级页面有 `/games`、`/study`、`/read`、`/software` 四个，再加第五个要把 `public/index.php` 里那张表
  和导航、页脚的链接一起整理一遍；窄屏下导航链接整块隐藏（模板原本就这样），
  所以页脚放了一排站点链接作为手机上的导航区，没有做汉堡菜单
- 查询构造器目前覆盖 `memos` / `pomodoros` / `novels` / `novel_chapters` 四张表，
  `auth` / `visits` / `messages` / `games` / `softs` / `system` 仍在写原生 SQL（它们多表 JOIN 与聚合，
  套链式 API 反而更难读）；新表要不要走构造器，按「有没有 JOIN」判断就行
- 资源监控只覆盖 PHP 与 MySQL 两层，没有操作系统级的内存 / CPU 曲线（原因见上文）
- PWA 只做到「能装 + 断网能看到看过的页面」这一层：
  **没有后台同步队列**（断网时提交的留言、番茄钟不会在恢复网络后自动补发，
  `sw.js` 是有意完全不碰 `/api/` 的，缓存一个写请求等于替用户重复提交一次）；
  **没有更新提示**（改了 `public/assets/` 下的东西要手动把 `sw.js` 的 `CACHE_NAME` 尾号加一，
  否则装过机的设备断网时拿到的还是旧的一份）；
  「安装到桌面」按钮依赖浏览器抛 `beforeinstallprompt`，
  有的浏览器（包括开发时用的这个内嵌面板）就是不抛，这时只剩地址栏里那个系统安装图标，
  页面本身不会有任何异常
- 只用一个 PHP 内置服务器跑是单进程，仅适合本地开发；正式部署请交给 Nginx / Apache + PHP-FPM

## 常见问题

**页面顶部出现红色提示"后端接口连不上"**
后端没启动或端口不对。最省事是双击 `start.bat`；手动的话在项目根目录执行
`php -S localhost:8000 -t public public\index.php`，
注意要用 `http://localhost:8000` 打开，而不是双击 HTML 文件。

**双击 start.bat 就一闪而过 / 报「不是内部或外部命令」**
先确认 `php -v` 在命令行里能跑。不能的话，把 `start.bat` 里那行回退路径
改成你机器上 `php.exe` 的实际位置（默认写的是
`E:\phpstudy_pro\Extensions\php\php7.3.4nts\php.exe`）。

**服务器起在哪个端口上？怎么停？**
端口记在 `var/running.port`，启动器自己也会打印。停止就双击 `stop.bat`——
它只结束那个占着端口的 `php.exe`；万一端口上跑的是别的程序，它会拒绝动手并告诉你 PID。

**我想改启动器里的提示文字**
改 `tools/launch.php` 或 `tools/stop.php`，不要往 `start.bat` / `stop.bat` 里写中文
（原因见上面「跑起来」那一节的说明）。两个脚本都能直接在命令行里跑，改完可立刻验证。

**提示"数据库账号或密码不对"**
先跑 `php database/doctor.php`，它会把当前连的是哪个实例、哪一步失败直接指出来。
检查 `src/config.local.php` 的 `db_user` / `db_pass`；phpStudy 的 MySQL 默认口令通常是 `root`，
而独立安装的 MySQL 8 口令是你安装时设置的那个。

本机装了**两套 MySQL**（Windows 服务 `MySQL80` 和 phpStudy 的 `MySQL5.7.26`），它们抢同一个 3306 端口。
谁先起来谁占着端口，`config.local.php` 里的口令就必须跟**当前占着 3306 的那一个**一致，
否则接口全部报这个错，前端的表现是"登录失败"、"后台"按钮永远不出现。
先确认现在连着的是哪一套：

```bat
netstat -ano | findstr ":3306"          :: 记下最后一列的 PID
powershell "Get-Service *mysql*"        :: 看 MySQL80 是 Running 还是 Stopped
```

`web_one` 库是**跟着数据目录走的**，两套实例各有各的同名库，互不相通。
换实例后要重新跑一次 `php database\install.php`，否则新实例里没有表。

**页面上的功能对不上（比如没有"个人中心"按钮）**
多半是浏览器拿了旧的 css/js 缓存。Ctrl + F5 强制刷新。
页面 HTML 与接口响应都设了 `no-store`，但静态资源仍可能被缓存。

**升级到新版本后报错「缺少列」**
执行 `php database/migrate.php`。它会把旧库补齐到最新结构（幂等，可反复跑），
不会动你的数据。跑完再执行一次 `php database/doctor.php` 确认。

**收不到验证 / 重置邮件**
本地开发默认 `mail_driver=log`，邮件不会真的发出去，而是写进 `var/mail/YYYY-MM-DD.log`，
里面有完整的链接，直接复制到浏览器就能用。
要真的发信就把 `mail_driver` 改成 `smtp` 并填好 `smtp_*`（配置模板见 `src/config.example.php`）。

**端口 8000 被占用**
换个端口，例如 `php -S localhost:8080 -t public public\index.php`，前端不用改任何代码（接口用的是相对路径）。

**中文用户名显示成问号**
数据库、表、连接三处都必须是 `utf8mb4`。用 `database/install.php` 建的库已经满足；
手动建库时漏了字符集就会这样，重建库即可。

**想用 phpStudy / Apache 部署**
把站点根目录指向 `public/`，`public/.htaccess` 会把 `/api/*` 交给 `public/index.php`，
并补上静态资源的安全响应头；`src/` 与 `database/` 留在根目录之外，这样源码不会被下载。
